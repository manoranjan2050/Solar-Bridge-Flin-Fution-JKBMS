WHAT THIS PROJECT IS
--------------------
Replace paid "Solar Assistant" software with a self-hosted Python script that:
  - Reads data from a Flin Fution solar inverter and JKBMS battery
  - Publishes ALL sensors to MQTT with Home Assistant auto-discovery
  - Allows changing inverter settings FROM Home Assistant (controls)
  - Runs as a systemd service on Raspberry Pi 4, auto-starts on boot

KNOWN ISSUES AND TODO
----------------------
  1. BMS CURRENT = 0A
     The JKBMS current reading is not decoded. In the type-02 frame at offset +158
     there are bytes that change but the encoding (signed/unsigned, scale factor)
     hasn't been confirmed. Need a reading where current is known (e.g., user says
     "battery is charging at ~20A") then check frame byte at +158 to decode it.
     Frame capture showed: 0x026E = 622 (when ~0.6A), 0xFFFFF370 (when discharging).
     Likely int32 LE in mA, but needs verification.

  2. BMS SOC FLUCTUATES (36% vs 46%)
     The BMS broadcasts two frame types. Sometimes we catch type-01 instead of type-02
     and the SOC offset doesn't apply. The read_all() now searches specifically for
     55 AA EB 90 02 (type-02) which helps but BMS still occasionally sends only
     type-01 in the 3.5s window we read.
     Fix: read for longer, or parse both frame types.

  3. BMS REMAINING CAPACITY UNSTABLE
     Offset +154 (uint32 LE, mAh) sometimes gives correct ~170Ah but sometimes
     gives huge values like 700-870Ah. This suggests the offset shifts depending on
     which frame type or variant is received. Added sanity cap at 1000Ah.
     May need to identify a more reliable offset or use a longer frame.

  4. QPIRI CHARGER PRIORITY SHOWS "GRID FIRST"
     User had configured "Solar first" in Solar Assistant. The inverter QPIRI field
     [16] = 0 = Grid first. Either the inverter reverted its setting or the field
     mapping is different for this firmware. The control to change it IS implemented
     (PPCP01 = Solar first) so user can set it from HA dashboard.


INVERTER PROTOCOL NOTES
------------------------
  Voltronic PI30 protocol over USB HID:
  - HID writes: 9 bytes (0x00 report-ID + 8 data bytes)
  - HID reads: 8 bytes of raw ASCII response per packet (NO count prefix byte)
    IMPORTANT: this inverter (0665:5161) returns 8 raw bytes per read, unlike
    some other Voltronic USB devices that return [count][data]. We include ALL
    8 bytes from each read packet.
  - CRC: Voltronic lookup table CRC (see _crc() in solar_bridge.py)
    For QPIGS: CRC = b7a9 (confirmed working)
  - Response format: starts with "(" followed by space-separated values
  - Set commands: respond with "(ACK" or "(NAK"

  QPIGI response field order (0-indexed after the "("):
    0:grid_v, 1:grid_hz, 2:ac_out_v, 3:ac_out_hz, 4:ac_va, 5:ac_w,
    6:load_%, 7:bus_v, 8:batt_v, 9:batt_chg_a, 10:batt_cap_%,
    11:heatsink_C, 12:pv_a, 13:pv_v, 14:batt_scc_v, 15:batt_dis_a, 16:status_flags


JKBMS PROTOCOL NOTES
--------------------
  JK new protocol (55 AA EB 90):
  - BMS broadcasts AUTOMATICALLY every ~1 second (passive mode, no request needed)
  - Frame type 02 = cell info
  - Old JK protocol (4E 57) is NOT used by this BMS
  - Between new-protocol frames, BMS also sends old-format per-cell data
    (pattern: XX 10 16 XX 00 01 02 00 00 CRC CRC, 11 bytes per cell)
    This is normal and can be ignored.
  - Reading strategy: drain buffer, wait 1.2s, read 700 bytes, search for 55AA02

  JKBMS live values (2026-06-07 morning):
    Cells: 3.308–3.391V (16 cells), pack: 52.5V
    SOC: 46%, Cycles: 100, T1: 33°C, T2: 33.5°C, MOS: 35°C
    Battery was discharging at ~30-60A during high load periods
    Battery was charging at ~22A when PV surplus (~2700W PV, ~1300W load)
